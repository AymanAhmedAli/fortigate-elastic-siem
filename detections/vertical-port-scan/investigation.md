# Investigation — Vertical Port Scan Detection

## Summary
Validated Rule 1 (Vertical Port Scan Detection) against real traffic
generated by an actual `nmap` scan, routed through a FortiGate firewall
and indexed in Elasticsearch. The detection logic correctly identifies
the scan as a significant statistical outlier compared to normal
background traffic from the same host.

## Evidence

### Raw Event Sample
A single logged connection attempt from the scan, as parsed by Logstash:

source.ip: 172.18.183.50
source.port: 45420
destination.ip: 8.8.8.8
destination.port: 31
srcintf: port1
dstintf: port2
policyname: LAN-to-WAN
action: timeout
trandisp: snat
transip: 172.28.22.85
sessionid: 5706


Every connection attempt in the scan shares the same `source.ip` and
`source.port` (45420), targets the same `destination.ip` (8.8.8.8),
and varies only in `destination.port` — the exact signature described
in `rule.md`.

### Aggregation Query Result
Query from `query.json`, run against the last 1 minute of traffic:

| source.ip | destination.ip | unique destination.port count |
|---|---|---|
| **172.18.183.50** | **8.8.8.8** | **911** |
| 172.18.183.50 | 34.95.113.255 | 1 |
| 172.18.183.50 | 34.120.127.120 | 1 |
| 172.18.183.50 | 34.107.243.93 | 1 |
| 172.18.183.50 | 151.101.129.91 | 2 |
| 172.28.22.85 (NAT'd Kali) | 8.8.4.4 | 1 |
| 172.28.22.85 (NAT'd Kali) | 8.8.8.8 | 1 |
> **Note:** `172.18.183.50` and `172.28.22.85` refer to the same
> host (Kali). The former is the pre-NAT source address; the latter
> is the FortiGate-translated (SNAT) address visible on the WAN side
> of the same connection.

### Finding
The scanning host (172.18.183.50) contacted 8.8.8.8 on **911 unique
destination ports** within the test window — **~45x** the detection
threshold of 20 unique ports. Every other source/destination pair in
the same window used 1-2 ports, consistent with normal DNS/HTTPS
client behavior. This is a clear, unambiguous true positive with no
observed false-positive risk from legitimate traffic in this dataset.

## Root Cause Note (Pipeline Debugging)
Two issues had to be resolved before this traffic was visible at all —
documented here because they are relevant to anyone reproducing this
lab, not because they are part of the detection itself:

1. **Wrong FortiGate product downloaded initially** — a
   "FortiFirewall" VM image was deployed instead of "FortiGate",
   which could never obtain a valid evaluation license. Redeployed
   with the correct `FGT_VM64` image.
2. **Kali bypassed the firewall** — Kali had a direct route to the
   hypervisor's gateway, so traffic to the internet never passed
   through the FortiGate at all. Fixed by setting the FortiGate LAN
   interface as Kali's sole default gateway (see `simulation.md`).

## Conclusion
Rule 1 is validated against real attack traffic. The 20-port /
60-second threshold holds a wide margin against the observed normal
traffic baseline (1-2 ports per destination), supporting the initial
"Medium" severity rating pending further tuning against a larger
traffic sample.
